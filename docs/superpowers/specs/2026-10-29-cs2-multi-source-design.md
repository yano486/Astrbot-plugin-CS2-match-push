# CS2 比赛推送：多数据源接入设计

日期：2026-10-29（Asia/Singapore）

状态：聊天中的功能范围与合并原则已确认；实现已在本地完成，待用户安装验收。

- 当前基线：`451959a450a416fc4fa4c357f87558429fe6b96e`，插件版本 `4.2.0`。
- 本地已获取该固定提交的 GitHub 官方源码包；普通 Git 克隆遇到连接重置，源码包不包含 Git 历史。

## 2. 不在本次范围内

- 不移植参考插件的额外新闻、排名、选手资料、逐图 Rating 和整套战报界面。

- 不在未经进一步确认时提交、推送、发布或部署到手机。

## 3. 原有功能的保留边界

原有赛程查询、战队搜索与关注、群管理、赛事等级/黑名单筛选、赛前提醒、改期通知、赛果、日报、赛事开幕提醒、图文推送、手动测试和配置导入导出继续保留。

仅 PandaScore 模式应维持原行为，升级已有配置时也默认维持此模式。

HLTV 模式通过相同的调度与投递逻辑提供功能，但不能保证两个来源具有相同的数据覆盖、赛事等级和字段。来源没有的数据必须标为未知或缺失，不能推测填充。

## 4. 实现方式选择

采用独立的数据源适配层，而不是在每个指令中添加两套请求分支，也不直接拼接两个完整插件。适配层负责来源选择、统一结构、来源状态与身份关联；原插件继续负责订阅、调度、投递和渲染。

预期模块职责：

- 现有 `client.py`：保留 PandaScore 客户端，不重写已正常工作的请求逻辑。
- 新数据源模块：定义统一接口、HLTV 抓取与解析、双源路由和身份关联。
- `main.py`：消费统一记录，切换配置时更新客户端及调度任务。
- `store.py`：保存新增配置、来源关联和稳定的通知身份。
- `config.py`、`_conf_schema.json`：校验模式、主源及 HLTV 专属配置。
- `web_panel.py`、`plugin_view.py` 和 `pages/management/`：扩展既有页面及 API。
- 测试和文档：覆盖数据迁移、解析、合并、调度和面板。

## 5. 配置与界面

新增配置语义：

- `data_source_mode`：`pandascore`、`hltv`、`both`，默认 `pandascore`。
- `primary_source`：双源模式下的主源，默认 `pandascore`。
- HLTV 配置：代理地址、浏览器回退开关、请求最小间隔、缓存期限和独立星级筛选。

界面在现有“高级维护”的数据源区域增加模式选择、双源主源选择和分别检查连接的操作；新手引导也支持这些设置。赛程条目显示实际来源、更新时间及必要的冲突/缓存提示，保持现有样式。

仅启用 HLTV 时不要求 PandaScore Token；启用 PandaScore 时仍验证其 Token。任一来源连接失败不可以伪装成配置检查成功。双源检查可以显示一个来源正常、另一个受阻。

Token、浏览器状态和含认证信息的代理地址不得在日志、配置导出或 Git 中泄露。

## 6. 统一数据与来源身份

统一记录尽量保留现有调度/渲染所需结构，并增加：

- 稳定的本地比赛/赛事/战队标识；不把不同来源的裸数字 ID 当成同一个对象。
- 原始来源及其 ID、页面 URL、抓取时间和缓存状态。
- 来源关联和合并状态；双源记录保留两边的原始身份。
- 冲突说明和缺失字段说明。

通知、任务、改期快照、自定义提醒和投递回执使用稳定的本地身份。Web API 和页面不再假定全部标识都能安全转换为 JavaScript `Number`；旧的 PandaScore 数字引用应继续可解析。

同一对象的来源关联一旦建立便持久化，不能因重启、切换主源或新增另一来源而改变已使用的通知身份。

## 7. 双源合并和冲突规则

优先采用明确的跨源关联。没有明确关联时，仅当战队身份、赛事上下文、开赛时间及已知赛制等信息一致到足以排除歧义时，才自动合并。

- 不仅凭“两支队伍名字相同”就合并比赛；同一天可能再次交手。
- 名称规范化不得抹去青训、女子队、二队等区别。
- 比分、比赛状态和开赛时间发生冲突时，采用所选主源，并显示冲突及双方更新时间。
- 不把两边不同比赛的比分、阵容等拼装成一个结果。
- 主源数据缺失时，可显示另一个已启用来源的记录，但必须明确实际来源；这不是自动修改模式。
- 无法确认关联时，保留独立条目并标注疑似重复，不强行合并。去重保证针对已确认关联的比赛，不能声称所有跨源重复都能自动识别。
- 已确认属于同场比赛的赛前通知、赛果和日报条目只保留一份，部分群发送失败后的重试仍按目标去重。

## 8. 关注战队与筛选

原有 PandaScore 战队关注记录必须保留，不能在模式切换时清空或把其 ID 直接当成 HLTV ID。

关联到 HLTV 时只接受明确或无歧义的匹配；不能关联的关注项标记为待关联，保留原记录，让用户知道其在 HLTV 模式下尚未生效。战队搜索结果携带来源，避免选错主队或青训队。

PandaScore 的 S/A/B 等级继续保持现有语义。HLTV 的星级采用独立筛选，不能硬换算为 S/A。已合并记录可使用 PandaScore 提供的确切等级，并注明来源；HLTV 独有比赛按其星级和关注/黑名单规则筛选。

## 9. HLTV 抓取与解析

参考项目的实现分层接入，而非复制其整个运行环境：

1. 读取尚有效的页面/解析缓存。
2. 使用 `curl_cffi` 获取被站点允许访问的页面，校验状态、类型及内容。
3. 按配置回退到长期复用的 Playwright Chromium 上下文。
4. 验证受阻时报告需要人工验证，验证由用户在浏览器中完成。
5. 解析得到赛程、赛事、战队和赛果，再转为统一结构。

独立控制页面请求间隔、并发与缓存，参考项目的默认低频设置；被挑战或限流后退避，不持续重刷。共享浏览器上下文，按使用量/运行时间回收，销毁插件时关闭所有自有资源。

检测到挑战页、错误页、缺少预期页面结构时不得缓存为正常赛事数据。抓取失败与“成功但没有比赛”必须使用不同的结果状态。

人工验证入口限制为管理员；远程查看浏览器默认仅本机监听并通过 SSH 隧道访问，不默认向局域网/公网开放无认证 VNC。验证状态不作为可跨机器随意复用的通用凭据。

仅 PandaScore 模式不启动 Chromium，不进行 HLTV 预热或人工验证服务启动。

## 10. 生命周期与在线切换

模式变化时统一更新客户端、查询路由和未来调度任务。使用配置代次或等效机制，防止切换前的异步请求返回后覆盖新模式数据。

- 当前查询和后台更新有来源独立的超时，HLTV 受阻不能拖住 OneBot 事件处理或 PandaScore 正常刷新。
- 两种来源的健康状态、最近错误、最后成功时间独立记录。
- 切换后不重发已经成功推送的赛前/赛果通知。
- 切换模式或主源本身不应制造“赛程变更”通知；改期比较需使用对应来源的新基线。
- 新配置保存失败时保留旧配置；切换失败清楚报告，不能留下表面已切换而任务仍使用旧源的状态。

## 11. 旧数据迁移

使用 `astrbot_plugin_cs2` 标识及其独立 `cs_data.json` 数据目录。旧版 `astrbot_plugin_cs_match` 不会被自动覆盖或读取；如需迁移，用户应先备份旧目录，再通过导出/导入迁移可编辑配置。首次必要写入前创建完整备份，只补充相关字段，不能丢弃当前插件的群、凭据、关注、提醒和通知回执。

旧的比赛/赛事/战队数字 ID 视为 PandaScore 身份。迁移覆盖通知记录、逐目标投递回执、比赛时间快照、自定义提醒和关联索引，并保持幂等。

没有多源配置的旧文件仍可加载为 PandaScore 模式。旧版配置导入不得删除新增的来源关联或使运行状态失联。用户配置备份与浏览器凭据必须分开管理。

## 12. 依赖、运行环境与许可

新增抓取依赖预期包括 `curl_cffi`、Playwright 和 `selectolax`。先检查现有环境兼容性，不降低 AstrBot 核心依赖版本，不修改系统 Python。浏览器内核属于额外运行依赖，明确记录安装与检查方法，不在插件加载时偷偷下载。

Android ARM64 chroot 中浏览器是否能够稳定启动、网络出口是否能正常访问 HLTV，需用户后续安装验收；本地解析测试不能替代此验证。此前 bubblewrap 失败不直接等于 Playwright 一定不能运行。

若复用参考项目的代码，保留其 MIT 许可和 `canxiaocai` 版权声明，并在文档标注来源；不替原插件其余代码擅自更改许可声明。

## 13. 测试与验收

本地测试不连接真实 QQ，不自动发送消息，也不通过高频访问验证反爬。

该基线源码未提供 `tests/` 目录，不能声称已有自动化回归已通过；实现前应先补充现有 PandaScore 行为的测试基线。

必须覆盖：

1. 现有 PandaScore 功能的基线回归。
2. 三种模式的配置校验、持久化、导入导出及新手引导。
3. 只启用 HLTV 时不要求 PandaScore Token，且不请求 PandaScore。
4. 只启用 PandaScore 时不初始化浏览器。
5. HLTV 正常/空赛程/挑战页/错误页/缺字段的本地 HTML 解析。
6. 双源 ID 碰撞、确认合并、歧义不合并、主源冲突处理。
7. 旧关注记录保留、跨源关联和青训队/女子队区别。
8. S/A 等级与 HLTV 星级分开筛选。
9. 切换或重启后不重复推送；部分目标失败后仅重试未成功目标。
10. 配置切换中的异步竞态、浏览器回收与资源释放。
11. 独立面板与 AstrBot 内嵌面板执行同样的来源操作。
12. 桌面和手机宽度下，原有页面布局与新增控件可用。

交付时说明已经运行的检查、未能运行的检查及手机端需要验收的步骤。完整回滚以升级前的插件文件和完整 `cs_data.json` 备份为依据，不通过清空用户数据回滚。
